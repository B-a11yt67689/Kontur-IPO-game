# IPO-017 — Получить состояние первого акта

Карточка составлена по контексту по поручению пользователя. Общие источники и
выбранные трактовки: `docs/ACT-ONE-DECISIONS.md`.

## Требования

Добавить `GET /sessions/{session_id}/acts/1` для участника указанной сессии
с `Authorization: Bearer <participant_credential>`. Ответ 200 — полный
ActOneSnapshot из IPO-016, включая сохранённый бросок, доступность бонуса,
ресурсы, фактический состав, найм и started_at. Никаких credential/digest.

Отсутствующий, неверный, чужой credential и JWT администратора дают 401 с
WWW-Authenticate: Bearer. Неизвестный UUID тоже 401. Только после проверки
участника проверяется фаза: до/после act_one или при отсутствии состояния —409.
Ошибка БД или настройки подключения — санитизированный503 без SQL/DSN/traceback.

Авторизация, статус и состояние читаются одним согласованным SELECT. Outer join
состояния позволяет распознать preparation и вернуть409 своему участнику,
а не401. GET не меняет данные, не вызывает RNG и не начисляет бонус повторно.
Переподключение новым HTTP-клиентом возвращает актуальное сохранённое состояние.

Файлы: `backend/app/act_one.py`, `act_one_api.py`, тесты
`backend/tests/test_act_one_snapshot.py`, раздел API в `backend/README.md`.
Использовать существующие schemas и transactional helpers. Переиспользование
auth для следующих действий допустимо без копирования больших блоков. При
будущих мутациях изменяемый state загружается после блокировки game_sessions,
а не из старого ORM-снимка до ожидания FOR UPDATE.

## Приёмка

- Участник с ролью и без роли читает свою активную сессию.
- Аноним, чужая сессия, admin JWT и неизвестная сессия дают401.
- Свой участник в lobby/preparation/после акта получает409.
- Сохранённые изменения видны после reconnect; повтор не вызывает RNG/запись.
- Авторизация и данные возвращаются из одного SELECT.
- Ошибки БД дают503 без раскрытия секретов.

Отчёт: `docs/tasks/IPO-017/report.md`. Доказательства PostgreSQL тестов и Ruff
передаются независимому ревьюеру с полным пакетом изменений и снимком.
