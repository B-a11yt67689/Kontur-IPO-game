# IPO-016 — Запустить первый акт один раз

## Требования

Добавить `POST /sessions/{session_id}/acts/1/start`, Bearer администратора.
Тело отсутствует или `{}`; клиентские поля (roll, balance, etc.) запрещены
Pydantic-схемой пустой команды с extra=forbid. Null трактуется как отсутствие.
При успехе 200 с полным снимком ActOneSnapshot (общая схема ниже).

В одной транзакции заблокировать строку game_sessions через FOR UPDATE.
Неизвестная сессия 404. Первая инициализация возможна только в preparation,
при назначенном капитане и всех четырёх ролях cto/cmo/people/cfo. Иначе 409.
Роли и капитан продолжают ссылаться на участников своей сессии; ограничения
существующей БД сохраняются. После начала status='act_one'.

Вызвать `secrets.randbelow(10)+1` единственный раз при создании состояния,
затем resolver IPO-015. Состояние сохраняется отдельной таблицей act_one_states,
PK=session_id, FK game_sessions с ON DELETE CASCADE. Baseline IPO-014:
баланс 675.00, 60 клиентов, 130 AP, две junior-команды, уровень найма 0,
вместимость 2, три эксперимента. Бросок 1 увеличивает AP до 140; 9 — клиентов
до 70. Остальные бонусы сохраняются доступными и не меняют метрики/команды.
Без дополнительных очков за команды в первом акте (решение C).

Повторный и параллельный start в act_one возвращает ТЕКУЩИЙ сохранённый снимок,
включая последующие покупки; не бросает кубик, не тратит/начисляет ресурсы.
Другие фазы 409. Если статус act_one, но состояния нет — конфликт, не пересоздание.
Состояние и статус фиксируются вместе, ответ только после commit; ошибки
подключения/записи/commit дают санитизированный 503 и полный откат. После commit
обновить статус в текущем WebSocket лобби; ошибка публикации не должна отменять
уже успешный запуск. Рабочая модель рассылки остаётся однопроцессной.

## Схема и структура

ActOneSnapshot: session_id UUID; act_number Literal[1]; status Literal['act_one'];
started_at datetime timezone; balance Decimal; clients int; action_points int;
hiring_level int; hiring_capacity int; hired_development_team_grades list[str];
experiments_per_development_team int; starting_bonus {roll:int, code:BonusCode,
description:str, available:bool}. Для 1 и 9 available=False, для остальных True.
Не возвращать credential/digest. Деньги в JSON — строки Decimal.

В `models.py` добавить ActOneState с полями для этих сохраняемых величин
(статус в game_sessions, code/description выводятся resolver из сохранённого roll).
Состав команд хранить JSONB списком; проверить в БД, что это массив; остальные
ограничения: AP/clients >=0, эксперименты >0, roll 1..10, hiring_level 0..1,
согласованность пар (level=0,capacity=2) или (level=1,capacity=3).
Миграция `0006_act_one_states` после `0005_role_assignments`, upgrade/downgrade
без изменения старых полей/данных; metadata согласована с Alembic.

Новые маршруты в `app/act_one_api.py` (APIRouter), операции и построение снимка
в `app/act_one.py`; main.py только подключает router. Общие схемы можно
разместить в новом `app/act_one_schemas.py`. API не импортирует main, избегать
циклических импортов. Авторизация участника для следующих задач будет отдельно.

## Приёмка

Тесты на настоящей PostgreSQL: обычный/повторный/параллельный запуск, RNG один
раз, повтор после покупки возвращает сохранённое (пока можно изменить запись
в тесте напрямую); результаты бросков 1,9 и отложенного бонуса; readiness и
фаза; auth до БД; неизвестный UUID; подставленные поля 422; чтение новым
соединением после ответа; ошибки записи И commit с откатом и без утечки;
WebSocket статус. Миграция сохраняет старые данные и каскад удаления,
проверить CHECK/PK/FK. Обновить expected revision в существующем schema-test.
Файлы: models.py, новые act_one*.py, main.py, миграция, tests/test_act_one_start.py,
необходимое изменение tests/test_database.py, docs/README по API.
