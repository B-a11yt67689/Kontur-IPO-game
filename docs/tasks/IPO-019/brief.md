# IPO-019 — Рассчитать P&L акта по готовым входам

Карточка реализации составлена по названию задачи из запроса пользователя и
переданным исходным материалам. Это не копия отсутствующей ссылки `brief`.

## Источники

Комплект `IPO-команда-2026-11-01`, разделы P&L и «Перенос денег и кредиты»
в `Проект Игра IPO/Метрики и формулы IPO.md`, строки 3–16 листа `8 PnL`

## Задача и границы

Добавить чистую Python-функцию `calculate_act_pnl(inputs: PnlInputs) -> PnlResult`
в `backend/app/pnl.py`. Входные и выходные структуры — неизменяемые dataclass.
Расчёт не обращается к БД, не меняет сессию и не добавляет HTTP endpoint.
Клиенты, рекламный бюджет и ФОТ уже рассчитаны вызывающим кодом.
Кредиты, округление клиентов, риски и завершение акта сюда не входят.

Входы: `act_number` (1–7), `average_price`, `orders_per_client`, `clients`,
`advertising_budget`, `marketing_payroll`, `development_payroll`,
`support_payroll`, `balance_at_start`. Число клиентов — целое >= 0;
денежные значения и число покупок — конечные Decimal >= 0; начальный баланс
может быть отрицательным. Булевы значения вместо целых и float вместо Decimal
отклоняются явно. Неверные типы дают TypeError, неверные значения — ValueError.

Константы акта задаёт сервер:

| Акт | unit_cogs | business_costs |
| --- | --- | --- |
| 1 | 1 | 30 |
| 2 | 1.1 | 45 |
| 3 | 1.2 | 60 |
| 4 | 1.3 | 80 |
| 5 | 1.35 | 100 |
| 6 | 1.4 | 120 |
| 7 | 1.45 | 140 |

Формулы:

```text
arpc = average_price * orders_per_client
gross_revenue = arpc * clients
total_cogs = orders_per_client * clients * unit_cogs
operating_costs = marketing_payroll + development_payroll
                  + support_payroll + business_costs
result = gross_revenue - total_cogs - advertising_budget - operating_costs
balance_after_result = balance_at_start + result
```

Результат содержит все величины слева, а также `unit_cogs` и `business_costs`.
Использовать Decimal, без перевода во float и без введения правила округления
до копеек: в источниках оно не согласовано. Реклама вычитается только один раз.
Отрицательные финансовый результат и конечный баланс допустимы.

## Приёмка

- Пример Excel акта 1: цена 1.9, покупок 1.3, клиентов 42, реклама 0,
  ФОТ маркетинга 10, разработки 90, поддержки 60, начальный баланс 675.
  ARPC 2.47, выручка 103.74, CoGS 54.60, Operating Costs 190,
  результат -140.86, баланс 534.14.
- Акты 2 и 3 того же Excel: клиенты 105/140, реклама 97.50/105.60,
  маркетинг 20/30, разработка 90, поддержка 60, цена 1.9, покупок 1.3,
  начальный баланс 534.14/330.84. Результаты -203.30/-218.20,
  остатки 330.84/112.64.
- Проверить нулевых клиентов, отдельный вычет рекламы, константы всех актов,
  дробные значения без округления до копеек, отрицательный баланс и валидацию.
- Сохранить существующие тесты. Выполнить pytest, Ruff и проверку формата;
  отдельно указать ограничения интеграционных проверок при отсутствии БД.

в IPO-018: 401 для неверного/чужого credential (включая admin JWT), 403 своей
другой роли, 409 до/после акта, 503 при недоступности БД.
Это расширение предыдущей задачи: pure calculate_act_pnl остаётся неизменным.

JSON принимает average_price, orders_per_client, clients, advertising_budget,
marketing_payroll, development_payroll, support_payroll. Все поля обязательны,
extra=forbid. clients — строгое целое>=0, bool/float не допускаются. Decimal
входы конечные>=0 (JSON числа или строки); NaN/Infinity, включая нестандартный
JSON NaN, дают безопасный422, не500. Неверный JSON/типы/лишние поля также422.
Клиент не задаёт act_number и balance_at_start: сервер использует1 и сохранённый
баланс. Ошибки Decimal при непредставимых величинах —422 с безопасным detail.

Decimal. Запрос read-only: не меняет balance, AP, клиентов, команды, phase,
бонусы, не запускает RNG и не записывает результат. Параллельная покупка
не влияет на денежный баланс, используется авторизованный согласованный SELECT.
Схемы в act_one_schemas.py, маршрут в act_one_api.py, операции авторизации
