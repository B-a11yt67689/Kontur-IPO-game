# IPO-020 — Проверить первый акт сквозным сценарием API

## Требования

Добавить `tests/test_act_one_end_to_end.py`: сценарий только через публичные HTTP
endpoint (кроме проверки сохранения новым соединением к PostgreSQL и фиксации
источника случайности тестом). Создать две сессии реальным admin login;
в каждой четыре участника с отдельными credential; preparation, капитан,
самостоятельный выбор четырёх ролей, снимок подготовки. Admin запускает акт,
участник получает snapshot, people покупает первую ступень, CFO получает P&L
preview IPO-019 по готовым входам Excel. Другие роли не могут делать эти действия.

Повторить start и покупку, переподключить TestClient, проверить отсутствие нового
броска, неизменность баланса 675.00 после preview, ровно одно списание AP,
сохранённые два junior, уровень/вместимость и бонус. После действий в первой
сессии состояние второй не меняется; чужой credential в read/hire/pnl даёт401.
Сохранённые состояния проверить новым engine. Credentials/digest отсутствуют
в игровых ответах. Сценарий для бонусов1(+10AP),9(+10клиентов) и одного deferred.
Входы P&L первых трёх актов уже покрыты pure-tests; здесь акт1 даёт -140.86 и
534.14. Не рассчитывать неформализованную клиентскую базу и не завершать акт.

Продуктовый код менять только для конкретного обнаруженного дефекта, сообщить
контроллеру перед этим. Основные файлы: новый тест и раздел проверки в backend/README.md.
Запустить полный pytest на настоящей выделенной PostgreSQL, Ruff check и format.
Зафиксировать команды, результаты и фактическую область проверки в report.md.
