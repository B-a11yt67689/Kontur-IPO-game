# IPO-018 — Купить первую ступень стратегии найма

## Требования

Добавить `POST /sessions/{session_id}/acts/1/hiring/upgrade`. Пустая команда
из IPO-016: нет тела, null или {}; лишние поля 422. Доступ только участнику
с ролью people этой сессии по его credential. Без/неверный/чужой credential
и неизвестная сессия — 401 с WWW-Authenticate. Свой участник без people — 403,
в том числе капитан и другие роли. JWT администратора не даёт права участника.

Авторизация до фазы; в одной транзакции блокировка строки game_sessions,
проверка active status act_one и чтение состояния. Только первая ступень:
при level=0 и AP>=30 списать 30 AP, level=1, capacity=3. Иначе недостаток AP
или неверная фаза: 409 без изменений. При уже купленном level=1 вернуть
текущий снимок 200 БЕЗ нового списания даже при AP<30. Повторные и конкурентные
вызовы идемпотентны. Ответ — полный ActOneSnapshot после commit.
Не нанимать третью команду автоматически, не менять деньги, клиентов,
эксперименты, исходный состав и одноразовые бонусы. Нет второй ступени в этом API.

Использовать общие операции авторизации и снимка без копирования блоков,
сохранять session row lock как общий порядок блокировок с IPO-016. SQL/commit
ошибки: полный откат и санитизированный 503. Код в act_one.py / act_one_api.py.
Документировать контракт и разницу между вместимостью и фактическим составом.

## Приёмка

tests/test_act_one_hiring.py: AP130->100 и 140->110, capacity2->3, roster две
junior; повтор/конкуренция списывают один раз; ровно30 и меньше30; разные роли,
аноним/чужая сессия/админ, неверная фаза, лишние поля; ошибки БД/commit без
частичного обновления; reconnect и повтор start возвращают покупку; session isolation.
